# 受入条件と確認例

現在はP0の起動確認用画面まで作成。以下の機能試験は実装後に実行するものであり、合格済みではない。環境検証の結果は [toolchain.md](toolchain.md) に記録する。試験データはすべて架空。

## 1. 自動試験の使い分け

| 層 | 対象 |
|---|---|
| JVM単体テスト | 金額・日付・文字数の検証、予算・割合・目標計算、バックアップの検証 |
| Android/Roomテスト | DAO、索引を用いた検索、参照制約、トランザクション、マイグレーション |
| Compose UIテスト | 保存、種別切替、入力エラー、復元確認など重要操作 |
| 実機手動確認 | ファイル提供元、再起動、回転、TalkBack、オフライン、性能 |

画面のすべての文言に機械的なテストを作るより、データが壊れないことと主要操作を優先する。

## 2. 基準データ

2026年11月に、食費650円（11/1）、交通費240円（11/2）、食費1,000円（11/2）、バイト代50,000円（11/3）を作る。10/31には支出500円、12/1には支出700円を作る。

| 指標 | 2026年11月の期待値 |
|---|---:|
| 支出 | 1,890円 |
| 収入 | 50,000円 |
| 収支 | 48,110円 |
| 食費 | 1,650円、87.3% |
| 交通費 | 240円、12.7% |
| 11/2の支出 | 1,240円 |
| 月予算30,000円の残り | 28,110円 |
| 食費予算1,000円との差 | 650円超過 |

`examples/backup-v1.json` はこのデータを収録。目標額100,000円・積立額20,000円の旅行目標も含める。進捗20%で、上の収支は変化しない。

## 3. 機能と境界

| ID | 操作・条件 | 期待結果 |
|---|---|---|
| T01 | 支出650円を保存してアプリ再起動 | 日付・カテゴリ・金額・メモを保持 |
| T02 | 金額空、0、負数、小数、1e3、円記号 | 取引として保存不可。入力を残す |
| T03 | 全角６５０、最大金額、最大+1 | 650として保存、最大は保存、最大+1は拒否 |
| T04 | 保存ボタン連打 | 1操作で1件。成功後に同内容を再度新規入力すれば別件として許可 |
| T05 | 食費650円を600円に編集 | 11月支出1,840円・食費1,600円へ更新 |
| T06 | 交通費240円を削除 | 確認あり。削除後の履歴・集計・予算に同時反映 |
| T07 | 支出から収入へ種別変更 | 収入カテゴリが必要。支出合計から除かれる |
| T08 | 10/31、11/1、11/30、12/1 | 各月に正しく分類。登録日時に左右されない |
| T09 | 2028/2/29、2026/2/29 | 前者は有効、後者は拒否 |
| T10 | 端末時刻2026/11/1 00:30 JST | 今日の初期値が11/1で、UTC日付の10/31にならない |
| T11 | 支出のない月、収入のみの月 | 支出0円、空グラフ。NaN/Infinityなし |
| T12 | 予算未設定、0円、超過、カテゴリ合計超過 | requirementsの各ルール通り。収入で予算が増えない |
| T13 | 前月コピー、既存予算あり、前月一部未設定 | 確認後に対象月全体を前月設定へ置換。半端な状態を残さない |
| T14 | 目標額超えの積立、目標の編集・削除 | 達成表示。収入・支出の集計は変わらない |
| T15 | 同日・同作成時刻に120件 | 3ページで全IDが1回ずつ表示。日合計は全120件分 |
| T16 | ページング中に取引編集、日付移動 | 一覧を再読込し、古いページ由来の重複なし |
| T17 | メモ200/201文字、絵文字含む | コードポイント基準で判定がUIと復元で一致 |

各試験は独立したfixtureから開始し、T05等の変更を別試験に持ち込まない。

## 4. バックアップとDB

| ID | 試験 | 期待結果 |
|---|---|---|
| B01 | 出力→空DBへ復元→再出力 | exportedAt/appVersionを除く業務データ・ID・日時が一致。配列順の差は許可 |
| B02 | 同じファイルを2回復元 | 件数増加なし |
| B03 | 例JSONを復元 | 基準表の金額・カテゴリ・目標と一致 |
| B04 | 不正JSON、必須欠落、未知フィールド、重複キー | 原因を表示し既存DB完全保持 |
| B05 | 不明version、JPY以外、金額文字列/指数/小数 | 既存DB完全保持、勝手な型変換なし |
| B06 | 重複UUID、参照先なし、kind不一致、収入のカテゴリ予算 | 全体拒否、部分挿入なし |
| B07 | 32MiB超、件数超、深い入れ子 | 読込を中止し、フリーズやデータ変更なし |
| B08 | ファイル選択/確認の取消 | DB変更なし |
| B09 | DB挿入途中に故障注入 | 全体ロールバック。以前の全テーブルが一致 |
| B10 | 書込途中のI/Oエラー・空き容量不足 | 完了と表示しない。DBに影響なし |
| B11 | 復元前に開いていた入力フォーム | 復元後に古い内容が再保存されない |
| B12 | 出力中に別処理で取引更新 | 一貫した時点のバックアップ。参照切れ・半更新なし |
| B13 | 実データ0件の正しいファイル | 0件への置換を明確に確認して適用。カテゴリは残る |
| B14 | 上限件数と最大文字長の合法データ | 出力でき、自分の出力を再入力できる |
| D01 | categoriesの参照中行を物理削除 | 外部キーで拒否 |
| D02 | DBバージョン更新 | 既存データのID・金額・参照を保持 |
| D03 | 既存DB再オープン | カテゴリの重複seed・上書きなし |

v1しかない時点で未存在のv2移行を作る必要はない。D02は最初のスキーマ変更時から必須とする。

## 5. 実機で確認すること

- 機内モードで追加・編集・削除・集計・予算・目標・ローカルファイル書出し/復元。
- 再起動、画面回転、バックグラウンド復帰、プロセス再生成で保存済みデータが保持される。
- 文字200%、横画面、TalkBack、キーボード表示時の入力・保存。
- データ消去/再インストール後、外部に保存したJSONから復元できる。実験は実データのない検証用端末/プロファイルで行う。
- マージ済みManifestに不要な権限がない。OSバックアップ除外は設定と可能な実機挙動の両方を記録。
- requirementsの性能条件で中央値を測定し、機種・OS・ビルド・件数・測定回数を添える。
