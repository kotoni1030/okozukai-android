# 要件定義

仕様版1.0。決定の根拠は [decisions.md](decisions.md)、データ型は [data-model.md](data-model.md) を参照。

## 1. 到達点

Androidで収入・支出をすばやく記録し、月とカテゴリから使い道を振り返れること。通信がなくても入力・閲覧・集計・目標管理ができること。データを自分でバックアップし復元できること。

## 2. 初期版の機能

| ID | 必須機能 | 完了条件 |
|---|---|---|
| F01 | 支出・収入の追加 | 金額、種別に合うカテゴリ、日付、任意メモを保存できる |
| F02 | 編集・削除 | 保存済み取引を修正でき、削除は確認後に実行。集計にも反映 |
| F03 | 日付別履歴 | 選択月の取引を新しい日付順に表示。日ごとの収入・支出を別表示 |
| F04 | カテゴリ集計 | 選択月の支出合計、内訳、割合を横棒と数値で表示 |
| F05 | 月全体の予算 | 月の上限、支出実績、残り額を表示 |
| F06 | カテゴリ予算 | 各カテゴリの上限、実績、残り額を表示 |
| F07 | 貯金目標 | 複数目標を作成・編集・削除。目標額と手入力した積立額の進捗 |
| F08 | JSON書き出し | 全データを1ファイルに保存。アプリ再インストール後も復元可能 |
| F09 | JSON復元 | 検証・内容確認後の全体置き換え。失敗時に既存データが残る |
| F10 | オフライン | ローカルファイルへのバックアップを含め、通信なしで主要機能が使える |

## 3. 入力と表示の共通ルール

- 支出・収入とも金額とカテゴリ必須。日付は今日、種別は支出を初期値とする。
- 金額欄は数字キーボード。全角数字は半角に正規化し、前後の空白を除去する。内部のカンマ・円記号・小数・指数表記・符号・空白は受け付けず、円の整数を求める。表示時だけ桁区切りを付ける。
- 取引額は1〜999,999,999円。予算は0〜999,999,999円。金額未入力を0に置き換えない。
- メモは任意、前後の空白を除去して最大200文字。空文字も許可。HTML等として解釈しない。
- 日付は1900-01-01〜2199-12-31の実在日。未来日も明示的に選べるが、選んだ月の集計に即座に含む。予約処理や将来通知はしない。
- 初回のカテゴリは未選択。以後の新規入力では種別ごとの直近選択を記憶してよい。種別を変えたら対応するカテゴリへ切り替える。
- 「保存中」の二重押下を防ぐ。同じ内容の別取引は許可するため、内容一致による勝手な重複排除はしない。
- 入力エラーは該当欄の近くに表示。保存失敗時は入力を残す。通常保存に追加の確認ダイアログは不要。
- 編集は元IDと作成時刻を保持。種別変更時にはカテゴリを整合させる。削除は金額と日付を示して確認する。
- 収支や目標の全削除機能は初期版では追加しない。

## 4. 集計と予算

対象月の1日以上、翌月1日未満の `date` を対象にする。記録を登録した月で集計しない。

| 指標 | 定義 |
|---|---|
| 月の支出 | 対象月のEXPENSEのamountYenの合計 |
| 月の収入 | 対象月のINCOMEのamountYenの合計 |
| 月の収支 | 月の収入 − 月の支出（財布や口座の残高ではない） |
| 月の残り予算 | 月全体の予算 − 月の支出 |
| カテゴリ残り予算 | その月・カテゴリの予算 − 対応カテゴリの支出 |
| カテゴリ割合 | カテゴリの支出 ÷ 月の支出。表示のみ小数第1位へ丸める |

- 未設定と0円を区別。未設定は「予算未設定」、0円の設定は「予算0円」。未設定で支出があっても超過判定しない。
- 超過時は「○円超過」。内部の残額は負数を維持。進捗バーだけ0〜100%に収め、数値は超過分を隠さない。
- 予算0円・支出0円では割合を計算せず支出0円を表示。予算0円・支出ありでは全額超過と表示する。
- 月全体とカテゴリ予算は独立した上限。両方の残額を合算しない。カテゴリ未設定の支出も月全体の実績には含む。
- カテゴリ予算の合計が月全体の予算を超える場合、差額を表示するが保存を拒否しない。
- 新しい月の予算は未設定。前月からコピーするボタンを用意し、既存設定がある月は確認後に月全体・全カテゴリを一括置き換えする。前月にない設定はコピー先でも未設定になる。自動繰越はしない。
- 支出0円ならグラフは「この月の支出はありません」。収入は支出グラフに含めない。割合の丸めで合計が100%とずれる場合がある。

## 5. 貯金目標

- 目標名1〜40文字、目標額1〜999,999,999円、積立額0〜999,999,999円。複数作成可。
- 積立額は利用者が実際の額を確認して更新する。入力ラベルは「現在の積立額」とし、「今回追加する額」と混同させない。
- 進捗＝積立額÷目標額。積立額が目標額を超えることも許可し「達成」と表示。描画の上限は100%、実額はそのまま表示する。
- 目標への積立は収支の記録に加算・減算しない。目標間で同じお金を重複して入力できるため、全目標の合計を資産額とは呼ばない。
- 削除しても収支には影響しない。期限や積立履歴の記録は後続候補とする。

## 6. 非機能要件

- 初期版はインターネット権限・ネットワークSDKなし。外部フォントや画像の取得も行わない。
- Roomはアプリ内部保存領域。手動JSONは暗号化しないことを出力画面で短く説明する。
- ローカルのファイル選択ならオフラインで書き出し・復元可能。利用者がクラウドの保存先を選んだ場合は、その提供元の通信条件に従う。
- システムの明暗テーマ対応。色だけで収入・支出・エラーを区別しない。TalkBack用ラベルと48dp以上の主なタップ領域を設ける。
- 縦画面優先。横画面と文字拡大でも保存ボタンが隠れず、入力中の回転で値を失わない。
- 通常再起動後は保存済みデータを保持。未保存フォームは画面回転と通常のプロセス再生成で可能な範囲の状態復元を行う。復元完了後の古いフォームは再適用しない。

## 7. 性能の目標（未測定）

暫定条件：Android 10以降・RAM 4GB程度の基準実機で、リリース相当ビルド、架空取引10,000件（1か月最大1,000件）。P0で実機に合わせ基準を確定する。

| 操作 | 暫定目標 |
|---|---|
| コールド起動から入力可能 | 中央値2秒以内（10回測定） |
| 保存タップから保存完了表示 | 中央値300ms以内（20回測定） |
| 月切り替えから集計表示 | 中央値300ms以内（20回測定） |
| 一覧スクロール | 連続操作で目立つ停止がない。フレーム計測も記録 |

目標未達なら先に読み込み範囲、SQL、再描画を調査する。推測だけで大きなライブラリや多層化を追加しない。APK容量・常駐メモリは実測値を記録して以後の比較に使う。現時点の速度保証ではない。
